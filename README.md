# Cs2LatencyDoctor

Бесплатный открытый инструмент для Windows: находит причины «пули не регистрируются», инпутлага
и дёрганости в Counter-Strike 2 — и показывает **доказательства замерами**, а не «оптимизируй всё».

## Зачем это нужно

Большинство «оптимизаторов для CS2» применяют список твиков и просят поверить на слово.
Этот инструмент делает наоборот: сначала измеряет, потом чинит, потом измеряет снова.

Ключевой принцип: **средний пинг никого не волнует**. Волнует неровность. Задержка со средним 1 мс
и всплесками до 14 мс ощущается хуже, чем ровные 10 мс. Поэтому меряем распределение, а не среднее.

## Что уже работает

| Проверка | Что смотрит |
|---|---|
| Задержка до роутера | джиттер и потери на твоём участке: машина — кабель — роутер |
| Задержка до интернета | тот же замер до внешнего узла: отделяет проблемы провайдера от локальных |
| Настройки сетевого адаптера | модерация прерываний, Green Ethernet, Gigabit Lite, EEE, Selective Suspend |
| Питание USB | разрешено ли Windows отключать USB-порты «для экономии» |
| Планировщик MMCSS | приоритет игр, NetworkThrottlingIndex |
| Настройки CS2 | fullscreen vs borderless, VSync, Reflex, MSAA |

## Честные ограничения

- **Ничего не меняет.** Пока это только диагностика. Применение исправлений с бэкапом и откатом — следующий шаг.
- **ICMP может быть заблокирован** фаерволом, антивирусом или политикой сети. Тогда инструмент честно
  сообщает «измерить не удалось» и **не** выдаёт это за 100% потерь. Есть запасной путь через `ping.exe`,
  который видит потери, но не миллисекунды.
- **Настройки масштабирования NVIDIA** в реестре не хранятся (только через NVAPI или панель драйвера).
  Инструмент не делает вид, что может их поправить автоматически.
- **Никаких гарантий по FPS.** Инструмент борется с неровностью, а не с нехваткой производительности.

## Сборка и запуск

```powershell
dotnet build -c Release
.\src\Cs2LatencyDoctor.Cli\bin\Release\net10.0-windows\cs2latency.exe --seconds 20
```

Параметры:

```
--seconds N   длительность замера сети в секундах (5..120, по умолчанию 20)
--json        отчёт в JSON (для GUI и автоматизации)
--selftest    самопроверка логики оценки на записанных данных, без обращений к сети
--help        справка
```

Код возврата: `0` — проблем нет, `2` — найдены проблемы.

## Самопроверка

```powershell
cs2latency.exe --selftest
```

Прогоняет логику оценки на **реальных записанных замерах**: «до исправления» (19 всплесков из 200)
и «после» (1 всплеск из 300), плюс сценарии блокировки ICMP и обрыва связи. Полезно, потому что
сетевые замеры доступны не на всякой машине, а правила оценки должны быть верными всегда.

## Структура

```
src/Cs2LatencyDoctor.Core/          движок: проверки, замеры, оценка
  CheckResult.cs                    модель находки: важность, объяснение, что можно сделать
  IDiagnosticCheck.cs               интерфейс проверки + контекст
  DiagnosticRunner.cs               запуск всех проверок и сборка отчёта
  Checks/
    NetworkLatencyCheck.cs          замеры до роутера и до интернета
    NetworkAdapterCheck.cs          настройки сетевой карты
    PowerCheck.cs                   питание USB и схема электропитания
    SchedulerCheck.cs               MMCSS и сетевой троттлинг
    Cs2ConfigCheck.cs               настройки CS2
    LatencyEvaluator.cs             правила оценки (вынесены, чтобы тестировать)
    SelfTests.cs                    записанные сценарии для самопроверки
  Windows/
    LatencyProbe.cs                 замер ICMP: .NET → ping.exe → «заблокировано»
    NetworkAdapterReader.cs         чтение параметров адаптера из реестра драйвера
    PowerConfigReader.cs            чтение параметров питания через powercfg
    Cs2Locator.cs                   поиск установленной CS2 и её конфигов
    RegistryValueReader.cs          безопасное чтение реестра
src/Cs2LatencyDoctor.Cli/           консольный интерфейс
```

## Планы

1. Применение исправлений: бэкап значений → правка → повторный замер → откат одной кнопкой.
2. GUI (WPF) с человеческим отчётом вместо консоли.
3. Пауза фоновых приложений (Dropbox, торрент, RGB-службы) на время игры.
4. История замеров: видеть, стало ли лучше после правок.
5. Windows 11: проверка режима HDR, MPO, оптимизаций оконного режима.
